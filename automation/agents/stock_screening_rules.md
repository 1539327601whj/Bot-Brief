# 低估精选 · 筛选规则章程

本文件是「低估精选」功能的规则来源。Java 侧实现位于
`backend/src/main/java/com/ai/daily/screener/ScreeningRules.java`，
代码顶部注释指向本文件。**改规则先改本文件，再改代码。**

上游同类文件：`automation/agents/etf_allocation_rules.md`（ETF/A股观察）。
本文件与它同一口径，不重复的部分不另立。

---

## 1. 角色

你是筛选器，不是荐股分析师，也不是择时交易员。

你做的事只有一件：**在公开行情数据上，按事先写死的规则，排除明显不合格的标的，
把剩下的按「便宜程度 + 质量 + 位置」排个序，交给用户人工核实。**

你不做的事：

- 不预测涨跌，不说「未来上升概率大」。
- 不说「现在适合入手」「建议买入」「可以加仓」。
- 不因为「最近跌得多」而推荐。跌幅只是背景，永远不进打分。
- 不因为进入了名单就暗示它安全。名单是**待核实清单**，不是结论。

输出用词固定：**观察候选**、**风险清单**、**需要你人工核实的**。
禁止词：买入、卖出、加仓、减仓、建议持仓、目标价、必涨。

## 2. 必须使用的数据

### 2.1 主数据（缺了就不能判，缺就剔除）

**池子清单与基本面来自两个不同的接口**，这不是随意拆的：

| 用途 | 接口 | 域名 | 取什么 |
| --- | --- | --- | --- |
| 池子（谁在视野里） | `datacenter-web` 的 `/api/data/v1/get`，`reportName=RPT_VALUEANALYSIS_DET` | `datacenter-web.eastmoney.com` | 代码、带市场后缀的代码、简称、总市值 |
| 基本面（判存活与打分） | `/api/qt/ulist.np/get` | `push2.eastmoney.com` | 下表全部字段 |
| 日线（价格位置） | `/api/qt/stock/kline/get` | `push2his.eastmoney.com` | 前复权收盘价 |

清单只负责「谁在池子里」，**基本面一律以行情接口为准**。清单哪天开始多返回 PE/PB，
那是第二套口径偷偷进来了，不允许拿它打分。

**池子是「最新交易日总市值前 N 只」，不是全市场。** 这决定了「扫描总数」带着一个市值下限，
结果页的口径摘要里必须写出这个下限，否则读者会把「扫描 500 只」误当成全市场股票数。

> **字段 ID 与接口前提都会漂移，用前先验。** 上表的含义来自一次真实探测，东财改口径不会通知。
> 在能联网的机器上跑：
>
> ```bash
> py -3 automation/scripts/verify_screener_fields.py
> ```
>
> 它会把真实返回值与上表逐条对照（含 `市净率 = 价 / 每股净资产` 这条交叉验证），
> 并顺带确认几件不能想当然的事：
>
> - 清单的 `filter` 参数**必须原样发出去**，不能百分号编码——服务端用 ANTLR 解析它且不做 URL 解码，
>   编码后直接回 `参数预处理错误: NoViableAltException`。脚本会**反向**验一遍（故意发编码版，期望它失败），
>   因为这条一旦失效，池子会静默变成空。
> - 行情批量的 `secids` 里，点和逗号必须原样保留，否则东财认不出 secid。
> - 池子的市值单位还是不是「元」、下限落在什么量级。
> - **响应头的 Content-Type 与字符集**——见下面两条，它们不会报错，只会让人查错方向或静默出错。
> - **行情批量一次能吃多少只**——实测出来的这个数直接决定 `screener.quote-batch-size`，
>   也直接决定一次筛选要打几次外呼。
>
> 退出码非 0 就说明有字段或前提不再成立——**先查清楚再用**，别让排雷规则建在错的假设上。

> **两个只能靠「读响应」发现的坑**（都栽过一次，记在这里免得换个语言重写时再栽）：
>
> 1. **`datacenter-web` 回的是合法 JSON，但 `Content-Type` 声明成 `text/plain;charset=UTF-8`。**
>    直接用「反序列化成 Map/字典」的默认写法会失败，报的还是
>    `no suitable HttpMessageConverter found for content type [text/plain]` 这种和真实原因
>    毫无关系的错——排查时会一路往网络、代理、限流上想，全想错。
>    正确做法是**取字节流、自己定字符集、自己解析**，让 Content-Type 声明成什么都不影响解析。
> 2. **响应没声明 charset 时，默认按 ISO-8859-1 解码会把中文变成乱码**，
>    而**这个乱码能通过 JSON 解析**（结构字符全是 ASCII），于是字段齐全、一只不少，
>    只有公司名是坏的，一路混进结果页且不报任何错。所以解码的默认值必须显式定死为 UTF-8
>    （RFC 8259 规定 JSON 必须是 UTF-8），服务端声明了别的才听它的。

> ⚠️ **东财按 IP、按接口限流。** 被限流时的特征是「TCP 连得上，但服务端一个字节都不回就把连接掐了」
> （Java 侧 `NoHttpResponseException`、Python 侧 `RemoteDisconnected`、浏览器 `ERR_EMPTY_RESPONSE`）。
> 这与「网络不通」的处置**完全相反**：网络不通重试无害，被限流时每次重试都在把封禁推得更深。
> 代码里对应 `MarketDataRateLimitedException` → HTTP 429 → 前端停掉自动重试。
> 校验脚本本身也要打十几次外呼，**不要连着反复跑**。

| 字段 | 是什么 | 不是什么 |
| --- | --- | --- |
| `f12` 代码 | 交易代码 | 不是统一社会信用代码 |
| `f14` 名称 | 证券简称 | 不反映真实经营状态 |
| `f2` 最新价 | 最新一笔成交价 | 不是复权价，与日线不可直接横比 |
| `f6` 成交额 | 当日成交金额 | 不是市值、不是自由现金流 |
| `f8` 换手率 | 当日换手 | 高换手不等于有流动性，低换手不等于没流动性 |
| `f20` 总市值 | 总股本 × 价 | 不是企业价值（EV） |
| `f21` 流通市值 | 流通股本 × 价 | 不是可自由卖出的金额 |
| `f23` 市净率 | 价 / 每股净资产 | 对轻资产公司几乎无意义 |
| `f26` 上市日期 | 上市日 | 不反映借壳前的历史 |
| `f37` ROE(加权) | 净利润 / 净资产 | 高杠杆能把 ROE 抬上去 |
| `f41` 营收同比 | 与去年同期比 | 季报与年报口径可能不同 |
| `f46` 净利同比 | 与去年同期比 | 基数效应会让同比失真 |
| `f49` 毛利率 | 毛利 / 营收 | 不同行业不可横比 |
| `f57` 资产负债率 | 负债 / 总资产 | **对银行是存款负债比，与制造业不同口径** |
| `f100` 所属行业 | 东财行业分类 | 不是申万/中信分类，无法精确对齐 |
| `f113` 每股净资产 | 净资产 / 股本 | 不剔除商誉，商誉减值会直接打掉它 |
| `f115` PE(TTM) | 价 / 滚动每股收益 | **亏损时为负或空，负 PE 看着很小是陷阱** |
| `f133` 股息率 | 近一年分红 / 价 | 过去分红不代表未来分红 |

### 2.2 次数据（缺了降级，不剔除）

| 数据 | 是什么 | 缺了怎么办 |
| --- | --- | --- |
| `f8` 换手率 | 见上 | 保留该只，标「换手率未确认」 |
| `f41` / `f46` | 见上 | 稳健档缺一个可保留并标降级；两个都缺或成长档缺任一个，剔除 |

### 2.3 日线（用于价格位置）

`push2his.eastmoney.com/api/qt/stock/kline/get`，`klt=101`、**`fqt=1` 前复权**、`lmt=250`。

**必须前复权。** 用原始价会在除权日显示假跌 30%，把正常分红股判成「便宜」。

日线抓取失败或最后一根超过 15 个自然日：**保留该只的基本面分，丢掉价格位置维并标降级，不淘汰**。

### 2.4 指数 PE 分位

只读项目自己的库 `market_valuation_history`（`indexCode` / `peTtm` / `pePercentile` /
`percentileMethod` / `tradeDate`）。**库里没有的，一律标「估值分位未接入」，不编。**

库里的数由 `automation/scripts/index_pool_sync.py` 每日写入，来源有两个且**不可混用**：

| `valuationSource` | 接口 | 算什么 |
| --- | --- | --- |
| `csindex` | `csindex-home/perf/indexCsiDsPe` | 中证官网给的 PE 历史，项目自算滚动分位 |
| `danjuan` | `djapi/index_eva/dj` | 蛋卷直接给的 `pe_percentile` |

**每个指数只取其中一个**，哪个写死在 `index-pool.json` 里，见 §5.3。
两个源在部分指数上差 22% 到 75%，混用会得到跳变的分位而页面上看不出来。

滚动窗口不足 10 年的指数（如科创50 只有约 6 年），窗口自然是 `min(10年, 可用长度)`，
方法名仍写 `CSI_PE_TTM_ROLLING_10Y`，但卡片上必须能看出该指数的**历史长度**，
否则读者会以为是满 10 年的分位。

**这个口径只属于指数。** 个股没有 PE 历史分位（§7），所以条件里那条
「PE 分位上限」（`pePercentileMax`）**只作用于指数**，见 §5.10。

## 3. 排雷规则（V1–V12，恒开，不可关闭）

「不会破产」是底线，不做成可选项。每条规则命中即剔除并计入口径摘要。

| # | 规则 | 字段 | 阈值 | 字段缺失 |
| --- | --- | --- | --- | --- |
| V1 | 退市 / ST / 壳 | `f14` | 含 `ST` / `*ST` / `退`，或 `N` / `C` 次新前缀 | 剔除 |
| V2 | 上市年限 | `f26` | 稳健 ≥3 年，成长 ≥2 年 | 剔除 |
| V3 | 市值 | `f20`，回退 `f21` | 稳健 ≥200 亿，成长 ≥50 亿 | 剔除 |
| V4 | 流动性 | `f6` / `f8` | 成交额 稳健 ≥1 亿、成长 ≥0.5 亿；换手率 ∈[0.2%, 15%] | `f6` 缺→剔除；`f8` 缺→保留并标降级 |
| V5 | 亏损 | 净利润 / `f115` | 净利 <0 或 PE(TTM) ≤0 | 都不可确认→剔除 |
| V6 | 资不抵债 / 高 PB | `f23` | PB ≤0 剔除；稳健 PB ≤8；成长 PB ≤12 | 剔除 |
| V7 | 高杠杆 | `f57` | 稳健 ≤65%，成长 ≤75% | 剔除 |
| V8 | 业绩崩塌 | `f41` / `f46` | 稳健：净利同比 ≥ -20% 且营收同比 ≥ -15%；成长：两者 ≥0 | 稳健缺一标降级、都缺剔除；成长缺任一剔除 |
| V9 | 低价股 | `f2` | <3 元 | 剔除 |
| V10 | 停牌 / 不可交易 | `f2` / `f6` | 价格为 0 或成交额为 0 | 剔除 |
| V11 | 金融地产口径不可比 | `f100` | 银行 / 保险 / 证券 / 多元金融 / 信托 / 房地产 | 缺→保留但标「行业不可确认」 |
| V12 | 绝对估值上限 | `f115` | 稳健 ≤30，成长 ≤45 | 剔除 |

### 为什么是这些数

- **负债率卡 65% 而不是 50%**：非金融 A 股中位数约 40–50%。卡 50% 会误杀现金流足以覆盖
  55–65% 负债的工业、公用、电信、交运。65% 大致是「正常经营杠杆」与「资产负债表紧张」的
  经验分界。成长档放宽到 75%，容纳重资本扩张期公司，同时排除困境尾部。
- **V12 必须有**：池内分位只说明「在这批里相对便宜」。没有绝对上限，一个整体高估的行业里
  最便宜的那只也会入选。
- **金融地产整体不纳入**：`f57` 对银行是存款/负债对总资产，天然 90%+，与制造业不是一回事。
  现有字段没有不良率、拨备覆盖率、核心一级资本充足率，**判不了银行的存活能力**，硬纳入
  等于编结论。剔除数量在结果页公开。

## 4. 因子与权重

归一化用**池内分位排名**（方向调整后 0–100，2%/98% 缩尾），不用绝对阈值映射：
不假设分布、对 `f46` 这种厚尾稳健、页面上读得通（「在同批候选中处于第 x 分位」）。

**稳健低估**（风险等级：中低）

| 维度 | 权重 | 子因子 |
| --- | --- | --- |
| 估值便宜 | 40% | PE ×0.50、PB ×0.30、股息率 ×0.20 |
| 盈利质量 | 30% | ROE ×0.50、负债率 ×0.30、毛利率 ×0.20 |
| 规模稳定 | 20% | 总市值 ×0.60、年化波动 ×0.40 |
| 价格位置 | 15% | 一年价格分位 ×0.60、距 52 周高点回撤 ×0.40 |

**低估成长**（风险等级：中）

| 维度 | 权重 | 子因子 |
| --- | --- | --- |
| 估值便宜 | 30% | PE ×0.60、PB ×0.40 |
| 成长 | 40% | 营收同比 ×0.40、净利同比 ×0.60 |
| 质量与生存 | 20% | ROE ×0.50、负债率 ×0.30、毛利率 ×0.20 |
| 价格位置 | 10% | 一年价格分位 ×0.60、距 52 周高点回撤 ×0.40 |

**不进打分、只作背景展示**：`f24` 60 日涨跌幅、`f25` 年初至今、主力净流入。
「跌了」永远不是入选理由。

### 降级与不足

- 子因子缺失 → 丢弃，按剩余子权重归一。
- 整维为空 → 丢弃该维，维度权重重新归一。
- **主导维度为空 → 判不合格**（稳健的「估值便宜」、成长的「成长」），因为那一维就是这一档的定义。
- 分数下限 **55**。
- 排序：总分 → 总市值 → 股息率(稳健)/净利同比(成长) → 代码升序（保证结果确定）。
- **每档同行业最多 1 只，全结果同行业最多 2 只。**
- 合格不足 2 只时**如实少给**并写明「本次合格候选不足」，**绝不凑数**。

## 5. 指数基金优先

用户明确要「破产、下市的风险低一点」，所以指数排在个股前面。

### 5.1 池子的单位是「指数」，不是 ETF

一条 = 一个**指数**（如「中证500」）。ETF 只是取价格位置与规模的**手段**：同一个指数
可能有好几只 ETF，本池只挑一只代表，够用即可。

这条决定了三件事：结果页按指数分组、估值按指数口径取、规模取自代表 ETF 的**基金规模**。

### 5.2 池子由 `backend/src/main/resources/screener/index-pool.json` 定义

Java 启动时加载并**严格校验**（非法 `category` / 重复 `indexCode` / 重复 `etfCode` /
未知 `percentileMethod` → **启动失败**）。Python 侧通过 `GET /api/index-pool` 读同一份，
**不在 `automation/` 下另存一份**——两边各存一份必然漂移。

| 字段 | 含义 | 注意 |
| --- | --- | --- |
| `indexCode` | 指数在**项目库**里的主键，如 `SH000300` | 对应 `market_valuation_history.index_code` |
| `indexName` | 指数中文名 | 卡片标题，不是 ETF 名 |
| `category` | `broad` / `strategy` / `sector` / `theme` / `overseas` / `other` | 决定分组与徽章 |
| `valuationSource` | **只能**是 `csindex` 或 `danjuan` | 见 5.3 |
| `percentileMethod` | 与来源一一对应，不可自选 | csindex → `CSI_PE_TTM_ROLLING_10Y`；danjuan → `DANJUAN_PE_TTM_PROVIDER` |
| `csindexCode` | 中证官网的入参代码，如 `000300` | `valuationSource == csindex` 时必填 |
| `danjuanCode` | 蛋卷的 `index_code` | `valuationSource == danjuan` 时必填 |
| `etfCode` / `market` / `etfName` | 代表 ETF | 价格位置与规模的来源 |
| `tracking` | 这只 ETF 跟踪的指数名 | 用于人工核对，不参与计算 |

`indexCode` 与 `csindexCode` **不是一回事**：前者是项目库里的键（带 `SH`/`SZ` 前缀），
后者是中证官网接口的入参（纯 6 位）。分开存是为了不把「库里的键」和「外部接口的参数」
混成一个字段——它们哪天不同步，混在一起就查不出来。

`etfCode` 允许为空（该指数没有合适的 ETF），但**第一版池子里不会有**：没有 ETF 的指数
价格位置与规模全是原因串，正是用户说的「空着的场景」。等跑顺了再放开。

### 5.3 每个指数只钉一个估值来源

`valuationSource` 只能是 **`csindex`（中证指数官网）或 `danjuan`（蛋卷）之一，写死在池子里**。

原因是这两个源**不是同一个口径**。实测：沪深300 两边 PE 一致（13.15 / 13.18）、
上证50 接近（10.95 / 10.69），但中证500（25.09 / 31.92）、中证1000（29.59 / 41.95）、
科创50（71.37 / 125.06）**差 22% 到 75%**。同一个指数今天取这个源、明天取那个源，
分位会跳变，而页面上看不出来。

`percentileMethod` 描述「这个数是怎么算出来的」；**可比性由 `valuationSource` 承载**，
不由方法名承载。所以：

**保留「不跨指数比 PE」，并新增：分位排序只允许发生在同一 `valuationSource` 的子组内部。**
结果页先按 `category` 分组，组内再按 `valuationSource` 分子组，**排序只在子组内做**
（`pePercentile` 升序 → `scaleYi` 降序 → `indexCode` 升序）。子组小标题必须写出该组的口径。

**子组内合格在前**：先 `qualified`，再 `unconfirmed`，最后 `blocked`；
只有同一状态内部才按上面那三个键排。结果是「合格的在上、缺数据的居中、被挡下的垫底」，
而不是把三种状态混在一起按分位排——那样「为什么这张卡排在后面」就看不出来了。
这三态是什么、怎么判，见 §5.10。

不许把这些子组合并成一个跨口径总榜。真要做总榜，得先立一套「跨口径可比」的指标
（例如各自相对自身历史的 z-score）并写进本文件，**没立规则之前不做。**

### 5.4 类别不再只限宽基

原文「只放宽基」放宽为：行业/主题指数可以进池，但必须带上 `category` 徽章，
且**不得与宽基混在同一个排序组**。宽基的风险提示（不会破产、分散）不适用于行业/主题，
后者的提示要按类别另写——这一条仍是留作后续的开放项。

### 5.5 池子怎么维护

1. `automation/scripts/build_index_pool.py` **只产候选**，输出
   `automation/agents/index-pool-candidates.json`，**绝不覆写正式池子**。
   它拿蛋卷的指数清单与新浪的 ETF 全量清单互相匹配，给出 confidence 与 `why`。
   **不假设「名字相同就是精确跟踪」**——510500 是中证500、159915 是创业板指，
   名字常常对不上。生成器只提案，绑定由人确认。
2. 人工把候选搬进 `index-pool.json`，逐条确认 `etfCode` 确实跟踪该指数。
3. 加/改条目后**必须**跑 `py -3 automation/scripts/verify_index_pool.py`，退出码非 0 不许提交。
   大改（比如一次搬进几十条）还要加 `--csindex-limit 0` 跑一遍全量核验——
   默认只抽查 5 个 csindex 源，新条目恰好不在抽查里的那部分等于没验过。
4. **搬完再跑一次 `py -3 automation/scripts/index_pool_sync.py`**（需要
   `BACKEND_API_URL` 与 `REPORT_INGEST_TOKEN`，只有部署机配了）。
   不跑的话，新指数在库里没有估值行、代表 ETF 的日线也没预取，它们的 PE / 分位
   会落到 §5.10 的 `unconfirmed`，日线要靠点击时的兜底额度——而那个额度是有封顶的
   （§5.7），几十条新指数会把额度一次用光。
   **这是「扩池」与「扩池立刻有用」之间唯一的一步，不能跳。**

### 5.6 数据来源与节奏

| 用途 | 接口 | 节奏 |
| --- | --- | --- |
| 中证系指数 PE 历史 | `csindex.com.cn/csindex-home/perf/indexCsiDsPe?indexCode=`（需 `Referer`） | **一天一跑**，每个指数约 320KB |
| 蛋卷全量指数估值 | `danjuanfunds.com/djapi/index_eva/dj` | 一天一跑，**一次请求覆盖全部 63 个指数** |
| ETF 前复权日线 | `web.ifzq.gtimg.cn/appstock/app/fqkline/get`（腾讯） | 日更预取**最后 260 根**写入 `etf_price_history`（`source=腾讯前复权日线`；东财那条线写 `东方财富前复权日线`，两者**不可混用**，见 5.9） |
| ETF 行情与规模 | `qt.gtimg.cn/q=`（腾讯，支持逗号批量） | 日更预取；点击时只作兜底且封顶 |
| ETF 兜底行情（价与成交额） | `hq.sinajs.cn/list=`（新浪，需 `Referer`） | 点击时最后兜底；**不提供规模**，规模那格写原因串 |

**csindex 遇 403 / 429 / 空响应 / 业务码非 200 时，整轮 csindex 段立刻中止，不写半截**，
保留库里的昨日值，页面自然显示昨天的 `valuationTradeDate`。这比写进一批半新半旧的值好。

预取 **260** 根而点击时只用 **250** 根，那 10 根是余量：一旦预取数掉到 250 以下，
`MA250` 与年化波动会**静默变空**（样本不足），页面上看不出是「预取少了」还是「这指数没有日线」。

指数块给：价格位置（与个股同口径，前复权日线）、规模与流动性、PE 与 PE 分位。
**任何一格取不到，都要写清「为什么缺 + 下一步怎样」，不留破折号、不填 0。**

### 5.7 取数兜底链

「好多价格和 PE 分位都是空的」不是同一件事：PE 分位缺是因为池子里没配估值来源（5.4），
价格位置缺是因为**东财一条日线都没回而当时没有任何兜底**。兜底链是后者的答案。

1. **指数行情**：东财 `push2 ulist` → 腾讯 `qt.gtimg.cn` → 新浪 `hq.sinajs.cn`。
   **指数日线**：内存缓存 → **`etf_price_history` 批量读库** → 东财 → 腾讯（封顶）→ 取不到就是取不到。
2. **日线以本地库为主，点击时不该有外呼。** 日线由每日同步预取入库（5.6），点击时**一次批量查询**
   取回整池。池子 200 条时「每只一条日线」= 200 次外呼，正是把 IP 封得更深的做法。
   外呼那条链（东财 → 腾讯）是**库为空时**的兜底，不是常态。
3. **每层只补上一层缺的那几只，不是整批重打。** 整批里挂了 2 只，就只产生 2 只的兜底外呼。
   兜底链的第一价值是消掉空白，第二价值是别把外呼量乘三。
4. **兜底源只在主源没给到该只时才启用**，用了哪几个源要写进口径摘要
   （「指数行情来源：东财 5 只、腾讯（兜底）2 只」「其中 N 只的日线来自本地预取库」）。
5. **额度是安全阀**（`screener.index-pool-max-live-fetches`，默认 10）。池子会扩到 200 条，
   而「每只一条日线」正是把 IP 封得更深的做法。额度用尽必须在摘要里写明少了几只——
   否则它和「这个指数本来就没有数据」看起来一模一样。
   **不许因为「反正有兜底」就把它调大。**
6. **冷却按源分开记。** 腾讯挨的限流不许锁掉东财的清单请求，否则页面上那句
   「东财在限流」就是假话；反过来也一样。限流本来就是按源、按 IP 计的。
7. **主源的限流信号不许被兜底抹掉。** 兜底救回来了也要照记主源的限流冷却，
   否则下一轮又会去打那个已经被封的源。兜底也失败时，保留主源那句「被限流」作为解释。
8. **读库失败 ≠ 这个指数没有日线。** 这是两件不同的事，说法也必须不同：
   库里查不到是「还没同步到」，查询失败是「这次没查成」。
   把后者写成前者，等于告诉用户一件不真的事。**也不许因为查询失败就把整块价格位置留空**——
   该退回外呼那条链继续取。
9. **估值整池一次读、且缓存一小时**（`screener.valuation-ttl-minutes`）。
   逐条查在几十条池子上无感，到 200 条就是 200 次往返。
   缓存**不设成一天**：用户下午点一次、16:30 同步完再点，若还看到旧数，他会以为这功能没在更新。

### 5.9 同一只 ETF 的日线只认一个口径来源

`etf_price_history` 的唯一键是 `(fund_code, trade_date, adjustment_type, source)`——
**`source` 在键里面**。所以同一天可以同时躺着东财行（`东方财富前复权日线`）和
腾讯行（`腾讯前复权日线`），两者是**两家公司各自的复权基准**。

读库之后**第一件事永远是按 source 分组、只留一条序列**，判据照 `etf_price_history` 的读法
（`automation/scripts/etf_report.py select_cached_price_series`，Java 侧同判据见 `EtfPriceSeriesSelector`）：

1. 按 source 分组，各自按日期排序、去重、剔掉非正收盘价与非前复权的行；
2. 取「最后一根日期最新」的那批；
3. 其中「尾部连续段最长」的胜出（相邻两根隔 1–4 个自然日算连续，覆盖周末），再平手则总根数多的胜出。

**直接按日期铺开会被静默换源**：曲线前段和后段来自两套复权基准，算出来的价格分位、回撤、
年化波动**每一个数都是错的，而每一根日线看上去都合法**。这类错误没有任何报错，
只能靠「挑出来之后不许混源」的断言盯着——见 `EtfBarFromDbTest`。

**不因为某天某个源挂了就切到另一个源**：那会让 250 根序列在中间换一次口径。
宁可短一截，也不要一条混源的曲线。

### 5.8 字符集：两个源与东财相反

东财是「响应头声明了 charset 就听它的，没声明才按 UTF-8」（RFC 8259 规定 JSON 必须是 UTF-8）。
**腾讯与新浪反着来：它们不声明 charset，内容是 GBK。** 所以那两个源一律**强制 GBK、不 sniff、
不看响应头**。默认值取错不会报错——GBK 的中文按 UTF-8 解出来是乱码，而乱码照样能被解析
（结构字符全是 ASCII），于是「沪深300ETF华泰柏瑞」变成一串问号，字段齐全、一个都不少、
任何地方都不报错。**这类损坏只能靠一条会红的测试盯着，不能靠注释。**

### 5.10 指数块的条件与三态（缺值不许静默剔除）

指数卡**也要过条件**，而且这些条件和个股那套**不是一回事**：

| 条件字段 | 对指数取哪个数 | 注意 |
| --- | --- | --- |
| `peMax` | 指数自身的 `peTtm` | 与个股同名字段，口径同为 PE(TTM) |
| `pePercentileMax` | 指数自身的 `pePercentile` | **只作用指数**，见下 |
| `marketCapMinYi` | 代表 ETF 的**基金规模** | 与个股市值下限**不是同一个口径**，理由串必须说出来 |

**留空即不限。** §3 里 30 / 45 那套 PE 默认值是**按个股档位（稳健 / 成长）定的**，
指数没有档位；凭空给指数造一个默认上限就是造规则（§6 第 4 条）。所以这一块，
用户没填的条件一律**不参与判定**，规则不替用户补一个数。

三态（DTO 字段 `qualification`，**永不为 null**）：

| 状态 | 何时 | 页面上 |
| --- | --- | --- |
| `qualified` | 有条件、有值、全部通过 | 「本次入选」 |
| `blocked` | 有条件、有值、至少一条不通过 | 列出「被哪条挡下、当时是多少」（如 `PE 分位 27.5% > 上限 30`） |
| `unconfirmed` | 有条件，但至少一条**缺值**（库里没估值行、日线没预取到） | 列出「哪条缺什么数据」 |
| `no_conditions` | 用户一条指数条件都没填 | 不做判定，页面明说 |

**不变式：`blocked` / `unconfirmed` ⟺ 理由串非空；缺值一律进理由串，不兜 0、不静默剔除**
（§6 第 1、4 条）。

**`blocked` 与 `unconfirmed` 的卡片不隐藏，保留在列表里。** 用户问的是「条件到底有没有用」——
只显示合格的那几张，恰好是最看不出条件在起作用的做法；把「谁被挡下、为什么」摆在明面上才是答案。

**`pePercentileMax` 只作用指数。** 个股没有 PE 历史分位：东财不给，只有价格分位（§7）。
拿它去筛个股，等于用一个不存在的数做判断。

## 6. 硬约束

1. 缺字段不许静默打分。默认剔除；只有 `f8` 与 `f41`/`f46` 之一允许降级不剔除，且每处降级都在页面上显示。
2. 不许跨口径比较：`f57` 不跨金融/非金融，PE 不跨指数，季报与年报不混当同一期。
3. 不许用负 PE 判「便宜」。V5 要求净利润 >0 且 PE(TTM) >0。
4. 不许因为缺数据就当成「没问题」。缺了就是缺了，标出来。
5. 数据时间必须随结果一起给出。用户看到的每个数字都要能对上「哪一日」。

## 7. 你明确不知道的事

这些**没有数据支撑，不许推断**，只能写进「需要你人工核实的」：

- 商誉规模与减值风险（`f113` 不剔除商誉）
- 大股东质押、减持计划、限售解禁
- 诉讼、处罚、问询函、审计意见类型
- 关联交易与资金占用
- 借壳 / 重组历史（`f26` 只给上市日，不给注入资产的时点）
- 实控人变更、控制权稳定性
- 行业景气度与政策变化
- 单只个股自身的 PE 历史分位（东财不给，只有价格分位。**所以 `pePercentileMax`
  只作用于指数，不许拿去筛个股**，见 §5.10）
- 任何未来价格、未来业绩

## 8. 输出纪律

每个入选标的必须能回答：**用了哪些数字、哪一日、哪一口径。**

读者无法复核的句子，不要写。凡是本文件第 7 节列的东西，只能出现在
「需要你人工核实的」清单里，而且必须是**提问式**的（「需核对是否存在大额商誉」），
不是**断言式**的（「该公司无商誉风险」）。

结果页底部必须出现：**本页仅为公开数据的规则化筛选结果，不构成投资建议、
证券推荐或买卖依据。**

### 口径摘要必须自洽

**各规则剔除数之和 + 进入打分数 = 扫描总数。** 对不上就是有 bug。
