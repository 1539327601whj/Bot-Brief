# 低估精选 · 筛选规则章程

本文件是「低估精选」功能的规则来源。Java 侧实现位于
`backend/src/main/java/com/ai/daily/screener/ScreeningRules.java`，
代码顶部注释指向本文件。**改规则先改本文件，再改代码。**

上游同类文件：`automation/agents/etf_allocation_rules.md`（ETF/A股观察）。
本文件与它同一口径，不重复的部分不另立。

---

## 1. 角色

你是筛选器，不是荐股分析师，也不是择时交易员。

你做的事只有一件：**在公开行情数据上，按事先写死的规则，排除明显不合格的标的，
把剩下的按「便宜程度 + 质量 + 位置」排个序，交给用户人工核实。**

你不做的事：

- 不预测涨跌，不说「未来上升概率大」。
- 不说「现在适合入手」「建议买入」「可以加仓」。
- 不因为「最近跌得多」而推荐。跌幅只是背景，永远不进打分。
- 不因为进入了名单就暗示它安全。名单是**待核实清单**，不是结论。

输出用词固定：**观察候选**、**风险清单**、**需要你人工核实的**。
禁止词：买入、卖出、加仓、减仓、建议持仓、目标价、必涨。

## 2. 必须使用的数据

### 2.1 主数据（缺了就不能判，缺就剔除）

**池子清单与基本面来自两个不同的接口**，这不是随意拆的：

| 用途 | 接口 | 域名 | 取什么 |
| --- | --- | --- | --- |
| 池子（谁在视野里） | `datacenter-web` 的 `/api/data/v1/get`，`reportName=RPT_VALUEANALYSIS_DET` | `datacenter-web.eastmoney.com` | 代码、带市场后缀的代码、简称、总市值 |
| 基本面（判存活与打分） | `/api/qt/ulist.np/get` | `push2.eastmoney.com` | 下表全部字段 |
| 日线（价格位置） | `/api/qt/stock/kline/get` | `push2his.eastmoney.com` | 前复权收盘价 |

清单只负责「谁在池子里」，**基本面一律以行情接口为准**。清单哪天开始多返回 PE/PB，
那是第二套口径偷偷进来了，不允许拿它打分。

**池子是「最新交易日总市值前 N 只」，不是全市场。** 这决定了「扫描总数」带着一个市值下限，
结果页的口径摘要里必须写出这个下限，否则读者会把「扫描 500 只」误当成全市场股票数。

> **字段 ID 与接口前提都会漂移，用前先验。** 上表的含义来自一次真实探测，东财改口径不会通知。
> 在能联网的机器上跑：
>
> ```bash
> py -3 automation/scripts/verify_screener_fields.py
> ```
>
> 它会把真实返回值与上表逐条对照（含 `市净率 = 价 / 每股净资产` 这条交叉验证），
> 并顺带确认几件不能想当然的事：
>
> - 清单的 `filter` 参数**必须原样发出去**，不能百分号编码——服务端用 ANTLR 解析它且不做 URL 解码，
>   编码后直接回 `参数预处理错误: NoViableAltException`。脚本会**反向**验一遍（故意发编码版，期望它失败），
>   因为这条一旦失效，池子会静默变成空。
> - 行情批量的 `secids` 里，点和逗号必须原样保留，否则东财认不出 secid。
> - 池子的市值单位还是不是「元」、下限落在什么量级。
> - **响应头的 Content-Type 与字符集**——见下面两条，它们不会报错，只会让人查错方向或静默出错。
> - **行情批量一次能吃多少只**——实测出来的这个数直接决定 `screener.quote-batch-size`，
>   也直接决定一次筛选要打几次外呼。
>
> 退出码非 0 就说明有字段或前提不再成立——**先查清楚再用**，别让排雷规则建在错的假设上。

> **两个只能靠「读响应」发现的坑**（都栽过一次，记在这里免得换个语言重写时再栽）：
>
> 1. **`datacenter-web` 回的是合法 JSON，但 `Content-Type` 声明成 `text/plain;charset=UTF-8`。**
>    直接用「反序列化成 Map/字典」的默认写法会失败，报的还是
>    `no suitable HttpMessageConverter found for content type [text/plain]` 这种和真实原因
>    毫无关系的错——排查时会一路往网络、代理、限流上想，全想错。
>    正确做法是**取字节流、自己定字符集、自己解析**，让 Content-Type 声明成什么都不影响解析。
> 2. **响应没声明 charset 时，默认按 ISO-8859-1 解码会把中文变成乱码**，
>    而**这个乱码能通过 JSON 解析**（结构字符全是 ASCII），于是字段齐全、一只不少，
>    只有公司名是坏的，一路混进结果页且不报任何错。所以解码的默认值必须显式定死为 UTF-8
>    （RFC 8259 规定 JSON 必须是 UTF-8），服务端声明了别的才听它的。

> ⚠️ **东财按 IP、按接口限流。** 被限流时的特征是「TCP 连得上，但服务端一个字节都不回就把连接掐了」
> （Java 侧 `NoHttpResponseException`、Python 侧 `RemoteDisconnected`、浏览器 `ERR_EMPTY_RESPONSE`）。
> 这与「网络不通」的处置**完全相反**：网络不通重试无害，被限流时每次重试都在把封禁推得更深。
> 代码里对应 `MarketDataRateLimitedException` → HTTP 429 → 前端停掉自动重试。
> 校验脚本本身也要打十几次外呼，**不要连着反复跑**。

| 字段 | 是什么 | 不是什么 |
| --- | --- | --- |
| `f12` 代码 | 交易代码 | 不是统一社会信用代码 |
| `f14` 名称 | 证券简称 | 不反映真实经营状态 |
| `f2` 最新价 | 最新一笔成交价 | 不是复权价，与日线不可直接横比 |
| `f6` 成交额 | 当日成交金额 | 不是市值、不是自由现金流 |
| `f8` 换手率 | 当日换手 | 高换手不等于有流动性，低换手不等于没流动性 |
| `f20` 总市值 | 总股本 × 价 | 不是企业价值（EV） |
| `f21` 流通市值 | 流通股本 × 价 | 不是可自由卖出的金额 |
| `f23` 市净率 | 价 / 每股净资产 | 对轻资产公司几乎无意义 |
| `f26` 上市日期 | 上市日 | 不反映借壳前的历史 |
| `f37` ROE(加权) | 净利润 / 净资产 | 高杠杆能把 ROE 抬上去 |
| `f41` 营收同比 | 与去年同期比 | 季报与年报口径可能不同 |
| `f46` 净利同比 | 与去年同期比 | 基数效应会让同比失真 |
| `f49` 毛利率 | 毛利 / 营收 | 不同行业不可横比 |
| `f57` 资产负债率 | 负债 / 总资产 | **对银行是存款负债比，与制造业不同口径** |
| `f100` 所属行业 | 东财行业分类 | 不是申万/中信分类，无法精确对齐 |
| `f113` 每股净资产 | 净资产 / 股本 | 不剔除商誉，商誉减值会直接打掉它 |
| `f115` PE(TTM) | 价 / 滚动每股收益 | **亏损时为负或空，负 PE 看着很小是陷阱** |
| `f133` 股息率 | 近一年分红 / 价 | 过去分红不代表未来分红 |

| 数据 | 是什么 | 缺了怎么办 |
| --- | --- | --- |

### 2.3 日线（用于价格位置）

`push2his.eastmoney.com/api/qt/stock/kline/get`，`klt=101`、**`fqt=1` 前复权**、`lmt=250`。

**必须前复权。** 用原始价会在除权日显示假跌 30%，把正常分红股判成「便宜」。

日线抓取失败或最后一根超过 15 个自然日：**保留该只的基本面分，丢掉价格位置维并标降级，不淘汰**。

只读项目自己的库 `market_valuation_history`（`indexCode` / `peTtm` / `pePercentile` /
`percentileMethod` / `tradeDate`）。**库里没有的，一律标「估值分位未接入」，不编。**

## 3. 排雷规则（V1–V12，恒开，不可关闭）

「不会破产」是底线，不做成可选项。每条规则命中即剔除并计入口径摘要。

| # | 规则 | 字段 | 阈值 | 字段缺失 |
| --- | --- | --- | --- | --- |
| V1 | 退市 / ST / 壳 | `f14` | 含 `ST` / `*ST` / `退`，或 `N` / `C` 次新前缀 | 剔除 |
| V2 | 上市年限 | `f26` | 稳健 ≥3 年，成长 ≥2 年 | 剔除 |
| V3 | 市值 | `f20`，回退 `f21` | 稳健 ≥200 亿，成长 ≥50 亿 | 剔除 |
| V4 | 流动性 | `f6` / `f8` | 成交额 稳健 ≥1 亿、成长 ≥0.5 亿；换手率 ∈[0.2%, 15%] | `f6` 缺→剔除；`f8` 缺→保留并标降级 |
| V5 | 亏损 | 净利润 / `f115` | 净利 <0 或 PE(TTM) ≤0 | 都不可确认→剔除 |
| V6 | 资不抵债 / 高 PB | `f23` | PB ≤0 剔除；稳健 PB ≤8；成长 PB ≤12 | 剔除 |
| V7 | 高杠杆 | `f57` | 稳健 ≤65%，成长 ≤75% | 剔除 |
| V8 | 业绩崩塌 | `f41` / `f46` | 稳健：净利同比 ≥ -20% 且营收同比 ≥ -15%；成长：两者 ≥0 | 稳健缺一标降级、都缺剔除；成长缺任一剔除 |
| V9 | 低价股 | `f2` | <3 元 | 剔除 |
| V10 | 停牌 / 不可交易 | `f2` / `f6` | 价格为 0 或成交额为 0 | 剔除 |
| V11 | 金融地产口径不可比 | `f100` | 银行 / 保险 / 证券 / 多元金融 / 信托 / 房地产 | 缺→保留但标「行业不可确认」 |
| V12 | 绝对估值上限 | `f115` | 稳健 ≤30，成长 ≤45 | 剔除 |

### 为什么是这些数

- **负债率卡 65% 而不是 50%**：非金融 A 股中位数约 40–50%。卡 50% 会误杀现金流足以覆盖
  55–65% 负债的工业、公用、电信、交运。65% 大致是「正常经营杠杆」与「资产负债表紧张」的
  经验分界。成长档放宽到 75%，容纳重资本扩张期公司，同时排除困境尾部。
- **V12 必须有**：池内分位只说明「在这批里相对便宜」。没有绝对上限，一个整体高估的行业里
  最便宜的那只也会入选。
- **金融地产整体不纳入**：`f57` 对银行是存款/负债对总资产，天然 90%+，与制造业不是一回事。
  现有字段没有不良率、拨备覆盖率、核心一级资本充足率，**判不了银行的存活能力**，硬纳入
  等于编结论。剔除数量在结果页公开。

## 4. 因子与权重

归一化用**池内分位排名**（方向调整后 0–100，2%/98% 缩尾），不用绝对阈值映射：
不假设分布、对 `f46` 这种厚尾稳健、页面上读得通（「在同批候选中处于第 x 分位」）。

**稳健低估**（风险等级：中低）

| 维度 | 权重 | 子因子 |
| --- | --- | --- |
| 估值便宜 | 40% | PE ×0.50、PB ×0.30、股息率 ×0.20 |
| 盈利质量 | 30% | ROE ×0.50、负债率 ×0.30、毛利率 ×0.20 |
| 规模稳定 | 20% | 总市值 ×0.60、年化波动 ×0.40 |
| 价格位置 | 15% | 一年价格分位 ×0.60、距 52 周高点回撤 ×0.40 |

**低估成长**（风险等级：中）

| 维度 | 权重 | 子因子 |
| --- | --- | --- |
| 估值便宜 | 30% | PE ×0.60、PB ×0.40 |
| 成长 | 40% | 营收同比 ×0.40、净利同比 ×0.60 |
| 质量与生存 | 20% | ROE ×0.50、负债率 ×0.30、毛利率 ×0.20 |
| 价格位置 | 10% | 一年价格分位 ×0.60、距 52 周高点回撤 ×0.40 |

**不进打分、只作背景展示**：`f24` 60 日涨跌幅、`f25` 年初至今、主力净流入。
「跌了」永远不是入选理由。

### 降级与不足

- 子因子缺失 → 丢弃，按剩余子权重归一。
- 整维为空 → 丢弃该维，维度权重重新归一。
- **主导维度为空 → 判不合格**（稳健的「估值便宜」、成长的「成长」），因为那一维就是这一档的定义。
- 分数下限 **55**。
- 排序：总分 → 总市值 → 股息率(稳健)/净利同比(成长) → 代码升序（保证结果确定）。
- **每档同行业最多 1 只，全结果同行业最多 2 只。**
- 合格不足 2 只时**如实少给**并写明「本次合格候选不足」，**绝不凑数**。

## 6. 硬约束

1. 缺字段不许静默打分。默认剔除；只有 `f8` 与 `f41`/`f46` 之一允许降级不剔除，且每处降级都在页面上显示。
2. 不许跨口径比较：`f57` 不跨金融/非金融，PE 不跨指数，季报与年报不混当同一期。
3. 不许用负 PE 判「便宜」。V5 要求净利润 >0 且 PE(TTM) >0。
4. 不许因为缺数据就当成「没问题」。缺了就是缺了，标出来。
5. 数据时间必须随结果一起给出。用户看到的每个数字都要能对上「哪一日」。

## 7. 你明确不知道的事

这些**没有数据支撑，不许推断**，只能写进「需要你人工核实的」：

- 商誉规模与减值风险（`f113` 不剔除商誉）
- 大股东质押、减持计划、限售解禁
- 诉讼、处罚、问询函、审计意见类型
- 关联交易与资金占用
- 借壳 / 重组历史（`f26` 只给上市日，不给注入资产的时点）
- 实控人变更、控制权稳定性
- 行业景气度与政策变化
- 单只个股自身的 PE 历史分位（东财不给，只有价格分位）
- 任何未来价格、未来业绩

## 8. 输出纪律

每个入选标的必须能回答：**用了哪些数字、哪一日、哪一口径。**

读者无法复核的句子，不要写。凡是本文件第 7 节列的东西，只能出现在
「需要你人工核实的」清单里，而且必须是**提问式**的（「需核对是否存在大额商誉」），
不是**断言式**的（「该公司无商誉风险」）。

结果页底部必须出现：**本页仅为公开数据的规则化筛选结果，不构成投资建议、
证券推荐或买卖依据。**

### 口径摘要必须自洽

**各规则剔除数之和 + 进入打分数 = 扫描总数。** 对不上就是有 bug。
