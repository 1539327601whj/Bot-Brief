# 代码查询 v2 · 规则章程

本文件是「代码查询 v2」（`/api/code-lookup/v2/**` 与前端结论仪表盘）的规则来源。
Java 侧实现位于 `backend/src/main/java/com/ai/daily/screener/v2/analysis/`，
代码顶部注释指向本文件。**改规则先改本文件，再改代码。**

## 0. 与其它章程的边界

- 本文件**只适用于「代码查询 v2」**。
- `automation/agents/stock_screening_rules.md`（低估精选）与
  `automation/agents/etf_allocation_rules.md`（ETF/A 股观察）的规则、禁止词表、
  「不构成建议」约束**原样保留**，不因本文件放宽。
- 两套口径不能互相印证：代码查询的阈值是**绝对口径**，低估精选的分位是**池内相对口径**。
  页面必须把这条差异写进「口径」页。

## 1. 角色

你是**规则化整理器**，不是荐股分析师，也不是交易员。

你做的事只有一件：在公开数据上，按事先写死的规则，回答四个问题：

1. 当前数据下，这只标的处于什么状态？（六维评分 + 结论标签）
2. 依据是什么？（每个维度、每个关键数字都带来源与日期）
3. 如果要等，等什么价位、什么信号？（参考买入区间、参考止损位）
4. 什么情况会让这个结论失效？（硬约束、事件、情景卡）

你不做的事：

- 不预测涨跌，不写「上涨概率」「预计涨幅」「目标价」。
- 不写「必涨」「稳赚」「保证收益」「建议满仓」「立即买入」「推荐股票」。
- 不因为「最近跌得多」而给高分；跌幅本身不是买入理由。
- 不在数据缺失时用 0 分或猜测值补齐。

## 2. 允许的输出词

结论标签**只能**取以下枚举之一，不得自由生成：

| 标签 | 分数区间 | 含义 |
|---|---|---|
| `值得重点关注` | 80–100 | 多维共振，但仍需人工核实 |
| `可分批关注` | 65–79 | 多数维度偏积极 |
| `观察等待` | 50–64 | 信号不一致，等待确认 |
| `偏谨慎` | 35–49 | 至少两项明显偏弱 |
| `回避` | 0–34 | 多项偏弱或触发硬约束 |
| `数据不足，暂不评级` | — | 覆盖率 <50% 或关键数据缺失 |

允许的区间措辞：`参考买入区间（规则计算）`、`参考止损位`。
**必须**同时出现：`不是买入建议`。

仍禁止的词：`必涨`、`稳赚`、`保证收益`、`目标价`、`建议满仓`、`立即买入`、
`推荐股票`、`上涨概率`、`下跌概率`、`概率 XX%`。

## 3. 数据与缺失

### 3.1 来源

只用免费公开源：东财（行情/日线/估值历史/财务/资金流/板块/新闻/公告）、
腾讯与新浪（行情/日线兜底）、中证指数官网（指数 PE、top10、行业权重）、
蛋卷（估值目录/周频历史）、Google News RSS（政策）。

同一序列只允许一个来源。**不跨源拼接同一个指标**：
PE 分位与 `peNow` 必须来自同一条东财估值分析序列；指数估值按来源分组，
csindex 走中证、danjuan 走蛋卷，绝不混源。

### 3.2 缺失

- 缺失值一律 `NULL`，不写 0，不插补。
- 每个子指标带 `available` 与 `note`；不可用时该子指标不参与该维度得分。
- 维度覆盖率 `dimCoverage = 可用子指标权重和 / 该维度子指标总权重`。
- 免费源不提供的项（分析师一致预期、北向、龙虎榜、机构持仓、L2 等）
  在页面上写「免费源不提供」，不进入评分，也不扣分。

### 3.3 新鲜度

- 价格：≤1 交易日 1.0，≤3 日 0.9，更久 0.5。
- 估值：≤7 天 1.0，≤30 天 0.8，更久 0.5。
- 财务：≤180 天 1.0，≤365 天 0.8，更久 0.5。
- 来源系数：官方/本地库 1.0，东财 0.95，兜底源 0.9。
- `confidence = coverage × 最小新鲜度系数 × 来源系数`。
  展示：≥0.80 高，0.60–0.80 中，<0.60 低。

## 4. 打分函数

所有子指标用**分段线性锚点**，不许用固定加减分：

```text
高值好：score(x) =
  0                                  x <= bad
  50 * (x - bad) / (neutral - bad)   bad < x < neutral
  50 + 50 * (x - neutral) / (good - neutral)  neutral <= x < good
  100                                x >= good

低值好：把 bad 与 good 对调后套同一函数。
```

三个锚点分别是「差 / 中 / 好」。单元测试至少断言三个锚点与两侧边界。

## 5. 覆盖率、总分与分数区间

```text
dimCoverage(d) = 可用子指标权重和 / 该维度子指标总权重
coverage = Σ(classWeight(d) * dimCoverage(d)) / 100

raw = Σ(可用维度 classWeight * dimScore) / Σ(可用维度 classWeight)
finalScore = 50 + (raw - 50) * coverage

scoreLow  = Σ_可用 classWeight * dimScore / 100
scoreHigh = scoreLow + Σ_缺失 classWeight * 100 / 100
```

- 缺失维度在区间下界按 0、上界按 100 处理。
- 页面显示「62（区间 48–76）」，并同时给出 coverage 与 confidence。
- **coverage < 0.50 时不输出数值结论**，只输出「数据不足，暂不评级」。

## 6. 硬约束（优先于分数）

| 条件 | 处理 |
|---|---|
| ST / *ST / 退市整理 | 总分上限 15，标签「回避」，标记 `ST` |
| 净资产 ≤0 或 BPS ≤0 | 上限 15，标记 `NEGATIVE_EQUITY` |
| 个股 PE_TTM ≤0 | 上限 45，标记 `LOSS_MAKING`，不能「值得重点关注」 |
| 停牌或价格陈旧 >5 交易日 | 不给结论，只给「停牌/数据不足」 |
| 成交额 <5000 万 | 上限 55，标记 `LOW_LIQUIDITY` |
| 覆盖率 <0.50 | 不给数值结论 |
| 上市 <120 交易日 | confidence 上限 0.60，技术维度部分可用 |
| 金融/地产健康 N/A | 不惩罚，只降覆盖率 |

硬约束必须进入 `hardFlags`，并在结论卡与「口径」页列出原因。

## 7. 事件调整

- 普通新闻标题**不参与** 100 分维度，避免标题党噪声。
- 独立的事件调整 `eventAdjustment ∈ [-5, +5]`，只统计高置信度事件：
  交易所公告、监管处罚/问询、业绩预告、回购/增持/减持、解禁、重大合同。
- 事件类型：
  - 正面：业绩预增、中标/订单、回购、增持、分红、政策支持、新产品/产能投产。
  - 负面：业绩预减、减持、质押、解禁、诉讼/处罚/问询、商誉减值、
    实控人变更、审计非标。
  - 中性/待定：人事变动、股权激励、并购重组。
- `finalScoreWithEvents = clamp(finalScore + eventAdjustment, 0, 100)`。
  事件调整**不改变六维分数**，只影响最终标签，并单独展示「事件调整 −3」及触发事件。
- 重大负面事件（审计非标、立案调查、大额减持/解禁、商誉暴雷）可触发结论封顶
  （最高「偏谨慎」或「回避」），但必须有公告/官方来源，并写入风险清单。
- LLM 不能修改事件极性或调整值。

## 8. 参考买入区间与止损

### 8.1 前置校验

以下任一不满足即 `WITHHELD`，并写明原因：

- 当前价 `P > 0`；
- 价格新鲜度 ≤3 交易日；
- 非停牌、非 ST/退市；
- coverage ≥0.50；
- 日线 ≥250 根。

### 8.2 估值锚

- 取 `PE_TTM > 0` 的历史点，窗口 `min(10 年, 可用)`，要求 ≥500 点且跨度 ≥3 年。
- `q25 = quantile(peHistory, 0.25)`，`q40 = quantile(peHistory, 0.40)`。
- `peNow` 必须是**同一条 PE 序列的最新点**，不能用行情接口的 f115；PB 同理。
- `Vlow = P * q25 / peNow`，`Vhigh = P * q40 / peNow`。
- PE 无效时改用 PB 的 q25/q40；PB 也无效则 `WITHHELD`（缺少可用估值锚）。
- 个股 PE 历史通常只有 2018 年起，页面必须标注「窗口 2018-01 至今」，
  **不能写「十年分位」**。

### 8.3 技术锚

候选支撑：`MA20, MA60, MA120, MA250, low20, low60, low120`，
只保留 `<= P * 1.02` 的。

```text
S1 = max(候选支撑)
S2 = max(候选支撑中 <= S1 * 0.98 的)，没有则 S1 - 1.0 * ATR14
Tlow  = S2 - 0.25 * ATR14
Thigh = S1 + 0.25 * ATR14
```

没有候选支撑：

```text
Thigh = P - 1.0 * ATR14
Tlow  = P - 2.5 * ATR14
```

### 8.4 区间合成

```text
L = max(Vlow, Tlow)
H = min(Vhigh, Thigh)
```

- `L <= H`：输出 `[L, H]`。
- `L > H` 且 `L - H <= 0.05P`：桥接为 `[H, L]`，注明「估值锚与支撑锚接近」。
- `L > H` 且差距 >5%：`WITHHELD`（估值与技术支持位不重合）。
- `H - L > 0.12P`：`WITHHELD`（区间过宽，精度不足）。
- 钳制：`H = min(H, P * 0.98)`；`L = max(L, P * 0.75)`。
- `P < L` → `BELOW_ZONE`，仍展示区间，但不写「等待回调」。
- `L <= P <= H` → `IN_ZONE`。
- `P > H` → `ABOVE_ZONE`，显示「距区间上沿 X%」。

### 8.5 止损

```text
stopTech = S2 - 0.5 * ATR14
stop = min(stopTech, L * 0.95)
if stop <= 0 or stop >= L * 0.97: stop = L * 0.95
```

- 止损距离 `(P - stop) / P`：个股 >18%、ETF/指数 >12% 时不输出止损，
  只写「止损距离过远，参考意义弱」。
- `P <= stop` → `BROKEN`，写「已跌破参考止损」，不输出新区间。
- 取整：股票 0.01，ETF 0.001，指数 0.01。

### 8.6 ETF / 指数

- 用跟踪指数 PE/PB 分位反推 ETF 价格（`ETF 价 × q25 / peNow`），
  标注「假设成分股盈利不变」。
- 技术支撑用 ETF 自身日线。
- 指数同时展示指数点位区间与对应 ETF 价格区间（若存在代表 ETF）。
- 跟踪指数用 `index-pool.json` 匹配；不在池内的走 `OffPoolIndexResolver`；
  非中证指数标「估值源未覆盖」。

## 9. 三情景推演

固定 `bull / base / bear` 三张卡。**不显示概率、不给目标价、不给时间窗、
不算隐含涨幅。**

| 情景 | 触发条件 | 文案骨架 | 失效条件 |
|---|---|---|---|
| 乐观 | 分数 ≥65，估值 ≥55，技术 ≥55，无硬约束 | 「估值与趋势同向；若盈利增速延续、估值分位不升破 80，当前状态偏积极」 | PE 分位 >80 或收盘跌破止损 |
| 中性 | 45 ≤ 分数 <65，或估值/技术方向相反 | 「估值与趋势未形成共振，等待方向确认」 | 放量突破区间上沿或跌破下沿 |
| 悲观 | 分数 <45，或技术 <35，或存在硬约束 | 「趋势/盈利/估值至少一项偏弱；若跌破参考止损，弱势可能延续」 | 重新站上 MA250 且估值分位回落 |

每张卡字段：

```json
{
  "key": "base",
  "label": "中性",
  "condition": "规则条件原文",
  "narrative": "规则模板生成的中文",
  "evidenceIds": ["ev:val:pe_percentile", "ev:tech:ma250"],
  "invalidation": "可观察的失效条件",
  "disclaimer": "条件推演，不是预测，不含概率与目标价"
}
```

不做 EPS × PE 价格预测：免费源没有可靠的盈利预测，外推增速会制造一个
看似精确、实际不可信的数字。情景卡回答「往哪个方向看、看什么信号验证」，
不回答「涨到多少」。

## 10. LLM 解读

- 只在用户点「生成解读」时调用；规则结论和区间不依赖 LLM。
- `EvidencePackBuilder` 把事实编号为 `ev:*`（含来源/日期/数值）。
- 输出严格 JSON：`sections[{heading, text, evidenceIds}]`。
- 校验器拒绝：
  - 未知 evidence ID；
  - 文本中出现 evidence 里没有的数字；
  - 第 2 节的禁止词；
  - 概率百分比或目标价形态。
- 校验失败回退规则模板文案，标记 `available=false` / `fallback=true`，
  页面不显示「AI 生成」。
- 缓存键：`code + snapshotId + rulesVersion + promptVersion`，30 分钟。
- 未配 key / 超时 / 空响应：分别给出真实原因。

## 11. 展示纪律

每个结论必须同时给出：

1. 规则依据（哪个维度、哪个锚点、什么值）；
2. 数据时间（`priceAsOf` / `valuationAsOf` / `financialAsOf`）；
3. 来源（东财 / 中证 / 蛋卷 / 腾讯 / 新浪 / Google News）；
4. 缺失项与覆盖率。

没有依据的数字不得出现在页面上。快照 ID 必须贯穿 core / detail / brief；
detail 发现快照变化时返回 `snapshotChanged=true`，前端重拉 core，禁止混用旧分数。

免责声明逐字保留，置于结论主卡和页脚：

> 本页仅为公开数据的规则化整理结果，不构成投资建议、证券推荐或买卖依据。

## 12. 变更管理

- 改阈值、权重、硬约束、区间公式：先改本文件，再改 Java，`rulesVersion` 递增。
- 改 LLM 提示词结构：`promptVersion` 递增，旧缓存自然失效。

  - 每条结论必须带 coverage/confidence；
  - 数据缺失时不得输出 0 分或数字区间。
