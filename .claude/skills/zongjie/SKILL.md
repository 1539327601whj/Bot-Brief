# 改动总结

产出**一句话**，能直接粘进编辑器的提交框。不改文件、不 `git add`、不 `git commit`、不 `git push`。

**这是一条快命令：最多跑 1～2 条 shell 命令就出结果。** 慢下来就失去意义了。

## 1. 拿改动清单

```
git status --short && git diff HEAD --stat
```

`git diff HEAD` 同时覆盖「已暂存」和「未暂存」，和编辑器 CHANGES 面板一致。

改动区为空 → 回「改动区是干净的，当前没有未提交的改动。」然后结束。

## 2. 看文件名写一句话

**默认不读 diff。** 文件名和目录就能说明改了什么，这个仓库尤其明显：

| 清单里出现 | 大概率是在做 |
| --- | --- |
| `StockPick.tsx`、`screener/` | 低估精选 |
| `index.css`、`ThemeContext`、一堆 `.css` | 深浅色主题 |
| `logging_setup.py`、`logback-spring.xml`、`web/` | 日志 |
| `etf_report.py`、`daily_report.py` | 日报生成 |
| `Subscription*`、`PushChannel*` | 订阅与推送 |
| `ShopAnalytics*`、`ContentGrowth*` | 店铺 / 内容增长 |

`--stat` 的行数能看出规模：几百行是重写，几行是改文案或配置。

**只有文件名完全看不出内容时**（比如清一色 `ServiceImpl.java`，或只有 `README`），才读一个文件的 diff：

```
git diff HEAD -- "<路径>" | head -60
```

看完就停，别顺手读第二个。

## 3. 输出

只有一行，包在代码块里方便复制：

````
<一句话>
````

- ≤ 40 字，口语化中文，像这个仓库已有的提交信息：
  - `修复开关功能，点「推送中」现在会变成「已暂停」`
  - `返回现在会回到你点进去时的位置，而不是首页最上面`
- 不要 `feat:`/`fix:` 前缀、不要 emoji、不要「本次提交」开头。
- **不要改动明细、不要文件数统计、不要贴代码。**
- 先说用户能感知到的变化，再说技术实现。

## 不要做的事

- 不跑测试、不跑 `tsc`、不跑构建。
- 不逐个文件读 diff。
- 不查悬空引用、不做代码审计、不评价代码好坏。
- 不为了「写得更准」补充阅读——一句话的精度不值这个时间。

代码块外最多补一句提醒（比如「有个改动看起来不完整」），没有就不说。
